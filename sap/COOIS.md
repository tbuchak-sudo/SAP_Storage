# COOIS — Production Order Information System

> **Рівень:** початківець → впевнений користувач  
> **Мета:** навчитися знаходити, фільтрувати та аналізувати виробничі замовлення, компоненти, операції, підтвердження та пов'язані дані.

## 1. Що таке COOIS

`COOIS` — Production Order Information System. Це інформаційна система для контролю та звітності щодо виробничих замовлень. SAP дозволяє виконувати вибірку за критеріями та переглядати дані замовлень на різних рівнях — наприклад, заголовок замовлення, операції та компоненти. citeturn0search0turn0search1

**Простими словами:** COOIS — це інструмент, через який можна поставити SAP питання на кшталт:

> «Покажи мені виробничі замовлення, які відповідають цим умовам, і покажи потрібні мені дані».

COOIS насамперед є **інформаційним/аналітичним інструментом**, а не місцем, де слід бездумно змінювати виробниче замовлення.

---

## 2. Для чого працівнику складу COOIS

COOIS корисний, коли потрібно:

- знайти виробниче замовлення;
- перевірити, до якого матеріалу належить замовлення;
- перевірити компоненти;
- переглянути операції;
- перевірити підтвердження;
- знайти пов'язані складські дані;
- звузити велику кількість замовлень до потрібної групи;
- дослідити ситуацію перед пошуком помилки.

SAP Help описує COOIS як інструмент shop-floor control з reporting-функціями для production orders; у сучасних системах також можуть бути доступні planned orders та додаткові поля залежно від версії й конфігурації. citeturn0search2turn0search3

# 3. Найважливіша ідея: рівні даних

Уяви виробниче замовлення як будинок.

### Рівень 1 — Header / Заголовок

Це загальна інформація про замовлення.

Наприклад:

- номер замовлення;
- матеріал;
- завод;
- дати;
- статуси;
- інші загальні атрибути.

### Рівень 2 — Items

Дані позиції/матеріалу замовлення.

### Рівень 3 — Components

Матеріали, які потрібні для виробництва.

Для складу цей рівень особливо важливий.

### Рівень 4 — Operations

Операції виробництва та пов'язана з ними інформація.

### Рівень 5 — Confirmations

Підтвердження виконання операцій.

### Інші списки

Залежно від версії SAP і налаштувань можуть бути доступні також:

- Object Overview;
- Order Headers;
- Items;
- Components;
- Operations;
- Confirmations;
- Goods Movements;
- Goods Movements with Errors;
- Purchase Orders;
- Capacities;
- Sequences;
- Document Links;
- інші списки.

SAP документує окремі object lists та Object Overview з ієрархічним відображенням замовлення та підлеглих об'єктів. citeturn0search1turn0search9

# 4. Як мислити при роботі з COOIS

Не починай з питання:

> «Яку кнопку натиснути?»

Починай з питання:

> «Що саме я хочу знайти?»

Наприклад:

### Завдання

Тобі кажуть:

> «Знайди виробничі замовлення для певного матеріалу за певний період».

Твій алгоритм:

1. Визнач матеріал.
2. Визнач завод.
3. Визнач період.
4. Вибери потрібний тип списку.
5. Виконай вибірку.
6. Перевір результат.
7. За потреби перейди до компонентів/операцій/підтверджень.
8. Збережи або проаналізуй результат.

# 5. Selection Screen — екран відбору

Екран відбору визначає, **скільки даних SAP буде шукати та що потрапить у результат**.

Це дуже важливо.

Поганий відбір:

> залишити майже все порожнім і натиснути Execute.

Результат може бути:

- дуже багато записів;
- довге виконання;
- складний для аналізу список;
- у гіршому випадку — проблеми з продуктивністю.

SAP прямо рекомендує використовувати хороші selection criteria та дати для обмеження обсягу даних. citeturn0search0

---

# 6. Дати

Дата — один із найважливіших способів звузити пошук.

Можна використовувати:

- абсолютну дату;
- діапазон дат;
- відносну дату, залежно від доступного поля/варіанту.

SAP окремо розрізняє абсолютні та відносні дати в COOIS. citeturn0search0

### Хороший приклад

Не:

> «Покажи все».

А:

> «Покажи виробничі замовлення для цього заводу за конкретний тиждень».

---

# 7. Матеріал

Якщо потрібно знайти замовлення для конкретного матеріалу, використовуй поле матеріалу на відповідному рівні відбору.

Важливо розуміти, що різні критерії можуть належати різним рівням даних.

Наприклад, матеріал може бути критерієм рівня замовлення/позиції, а робочий центр — рівня операції.

---

# 8. Дуже важлива особливість Work Center

Це одна з речей, на яких часто помиляються нові користувачі.

SAP документує випадок, коли користувач задає матеріал і робочий центр, а у результаті бачить також інші операції цього замовлення.

Чому?

COOIS — **order information system, а не operation information system**. Якщо замовлення відповідає критерію через хоча б одну операцію з потрібним work center, результат може містити інші операції цього ж замовлення. Це стандартна поведінка. citeturn0search0

### Простий приклад

Замовлення №100001 має:

- Operation 0010 → Work Center A
- Operation 0020 → Work Center B
- Operation 0030 → Work Center C

Ти відбираєш Work Center A.

Не роби висновок:

> «Якщо в результаті є B і C — COOIS зламався».

Замовлення було знайдене через A, а список може показувати пов'язані операції цього замовлення.

---

# 9. Execute

Після введення критеріїв запускається вибірка.

Перед Execute зроби коротку перевірку:

- правильний завод?
- правильний матеріал?
- правильний період?
- правильний тип замовлення?
- потрібний статус?
- немає випадково надто широкого відбору?

---

# 10. Аналіз результату

Отримавши список, не дивись тільки на перший рядок.

Перевір:

1. кількість замовлень;

4. статуси;

# 12. Object Overview

Object Overview показує замовлення разом із підлеглими об'єктами в ієрархічному вигляді. citeturn0search1

Умовно:

```text
Production Order
│
├── Header
├── Item
├── Components
│   ├── Material A
│   ├── Material B
│   └── Material C
├── Operations
│   ├── 0010
│   ├── 0020
│   └── 0030
└── Confirmations
```

Це дуже зручно для розуміння структури замовлення.

# 13. Максимальна кількість замовлень

У COOIS існує обмеження максимальної кількості замовлень, що відображаються.

SAP зазначає, що система може прочитати всі замовлення, але показати лише обмежену кількість. citeturn0search0

Тому:

> «Я бачу 500 замовлень»

не завжди означає:

> «У системі існує тільки 500 замовлень, які відповідають критеріям».

Потрібно перевіряти налаштування та умови вибірки.

---

# 14. Deleted orders

Замовлення з deletion flag/indicator можуть не потрапити у звичайний результат залежно від вибраних параметрів.

SAP документує можливість включення відповідного прапорця для відображення таких замовлень. citeturn0search0

---

# 15. Planned Orders

У відповідних сценаріях COOIS може працювати також із planned orders.

Але SAP зазначає, що вибірка planned orders не обов'язково означає показ **усіх** planned orders: враховуються релевантні для виробництва типи. citeturn0search0

# 16. Продуктивність

### Погано

```text
Plant = порожньо
Material = порожньо
Date = порожньо
Work Center = порожньо
```

### Краще

```text
Plant = конкретний завод
Date = конкретний період
Material = конкретний матеріал
```

SAP пояснює, що selection на рівні заголовка виконується до перевірок на рівні операцій; якщо на першому етапі вибирається дуже багато замовлень, подальша перевірка операцій може бути дорогою за часом. citeturn0search0

# 17. Практичний сценарій для складу

## Ситуація

Виробництво каже:

> «Мені потрібно перевірити, які виробничі замовлення потребують матеріалу X».

### Дії

1. Відкрити `COOIS`.
2. Вибрати відповідний тип замовлення.
3. Вказати матеріал X.
4. Вказати завод.
5. Встановити необхідний період.
6. Execute.
7. Перевірити список.
8. Перейти до компонентів.
9. Перевірити кількість.
10. За потреби перевірити рухи/підтвердження.

# 19. COOIS — чого НЕ робити

Не:

- запускати дуже широкий відбір без потреби;
- робити висновок про помилку через незрозумілий список операцій;
- плутати planned order і production order;
- вважати результат повним, якщо спрацювало обмеження кількості;
- ігнорувати статуси;
- змінювати дані без розуміння процесу.

# 20. Міні-тест

### Питання 1
Для чого головним чином використовується COOIS?

A. Для форматування Excel  
B. Для інформаційного аналізу виробничих замовлень  
C. Для створення користувачів  
D. Для зміни пароля

**Правильна відповідь: B**

### Питання 2
Чому важливо обмежувати вибірку датами?

**Відповідь:** щоб не змушувати систему обробляти непотрібний великий обсяг даних і отримати керований результат.

### Питання 3
Чому після відбору за Work Center можуть бути видимі інші операції?

**Відповідь:** COOIS працює як order information system; замовлення може бути відібране через одну операцію, після чого в результаті можуть відображатися інші операції цього замовлення. citeturn0search0

### Питання 4
Що робити, якщо результатів занадто багато?

**Відповідь:** звузити selection criteria — насамперед період, завод, матеріал та інші релевантні критерії.
